# 💻 사이클1: 사전학습

장기판 초기화를 어떻게 구현할지 설계해본다. 토론 활동의 재료를 만드는 단계.

## 🧪 실험1: 보드 초기화 설계

### 📝 해볼 것

코드를 작성하지 않고, 설계만 해본다.

1. 장기판을 어떻게 표현할 것인가?
2. 기물을 어떻게 표현할 것인가?
3. 초기 배치를 어떻게 설정할 것인가?

### 🔎 관찰할 것

| 질문                         | 내 답 |
|----------------------------|:---:|
| 장기판은 어떤 자료구조로 표현할 것인가?     |     |
| 기물은 어떤 정보를 가지는가?           |     |
| 위치 정보는 누가 관리하는가? (보드? 기물?) |     |
| 빈 칸은 어떻게 표현하는가?            |     |

## 🧪 실험2: 상태 분류

### 📝 해볼 것

장기 게임에서 변하는 정보와 변하지 않는 정보를 분류한다.

### 🔎 관찰할 것

| 변하는 정보 (상태)        | 변하지 않는 정보 |
|--------------------|:---------:|
| 예: 기물의 위치          | 예: 보드의 크기 |

### ❔ 추가 질문

| 질문                       | 내 답 |
|--------------------------|:---:|
| 상태가 변할 때 누가 변경하는가?       |     |
| 상태가 외부에 노출되어도 괜찮은가?      |     |
| 상태가 잘못 변경되면 어떤 문제가 생기는가? |     |

## 🧪 실험3: 기물 이동 시 조건문 폭발

### 📝 해볼 것

코드를 작성하지 않고, 설계만 해본다.

1. 각 기물(차, 마, 상, 사, 장, 포, 졸)의 이동 규칙을 나열
2. 이동 가능 여부를 if/switch로 작성한다고 가정
3. 조건문이 몇 개나 필요할지 예상

### 🔎 관찰할 것

| 항목               | 기록 |
|------------------|:--:|
| 기물 종류 개수         |    |
| 각 기물별 이동 규칙 개수   |    |
| 예상되는 조건문 개수      |    |
| 가장 복잡한 기물의 이동 규칙 |    |

## 🧪 실험4: 확장의 어려움

### 📝 해볼 것

다음 상황을 가정하고 분석:

1. 새로운 기물 "용"을 추가한다면?
2. 기존 기물의 이동 규칙이 변경된다면?

### 🔎 관찰할 것

| 질문                        | 내 답 |
|---------------------------|:---:|
| 새 기물 추가 시 수정해야 하는 곳은?     |     |
| 기존 기물 규칙 변경 시 영향 범위는?     |     |
| 조건문이 한 곳에 모여 있으면 생기는 문제는? |     |
| 조건문 없이 이동 규칙을 처리하는 방법은?   |     |

- [ ] 기물별 이동 규칙 정리표
- [ ] 예상 조건문 개수와 문제점

- Q. 분석한 기물별 이동 규칙을 정리하고, 예상되는 조건문 개수와 잠재적 문제점을 작성해 주세요.

## 📌 이번 사이클에서 답할 질문

- 장기판의 상태는 무엇인가? 
- 기물의 상태는 무엇인가?
- 상태를 어떤 객체가 관리해야 하는가?
- 불변과 캡슐화는 왜 필요한가?
- 기물마다 다른 이동 규칙을 어떻게 처리하는가?
- 조건문(if/switch)은 언제 문제가 되는가?
- 다형성은 어떤 문제를 해결하는가?
- 새 기물을 추가할 때 변경 범위를 어떻게 최소화하는가?
