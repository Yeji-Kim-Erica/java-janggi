## 🧪 실험2: 저장 요구 분석

### 📝 해볼 것

다음 요구사항이 추가된다고 가정:

1. 게임 중간에 저장하고, 나중에 이어할 수 있다
2. 여러 게임을 동시에 진행할 수 있다
3. 게임 기록을 조회할 수 있다

### 🔎 관찰할 것

| 질문                      | 내 답                                                                                                                                                                        |
|-------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 어떤 정보를 저장해야 하는가?        | 게임의 고유 ID, <br/> 각 게임별 진행 상황(보드판의 상태, 플레이어의 차례, 보드판 위 기물들의 팀 정보) 등                                                                                                         |
| 언제 저장해야 하는가?            | 보드판의 상태가 변할 때마다 <br/> (보드판의 상태가 변하는 시점과 팀의 차례가 변하는 시점이 동일하므로 보드판의 상태가 변하는 시점으로 통일)                                                                                         |
| 어디에 저장해야 하는가? (파일? DB?) | 인터넷 연결이 없이 로컬에서만 플레이한다면 파일, <br/> 인터넷 연결이 가능하다면 DB를 활용한다.                                                                                                                  |
| 저장/조회 로직은 어디에 있어야 하는가?  | 적절한 시점에 저장 및 조회를 하기 위해서는 게임의 전체 흐름을 알고 있는 Controller에서 저장 시점을 관리해야 함. 저장/조회의 메서드를 호출하는 시점을 Controller가 결정함. 저장 및 조회 **로직**의 경우, 데이터를 다루는 새로운 책임이 등장한 것이므로 새로운 클래스로 구현되어야 함 |

### 🗂️ LMS+ 제출

- **Q. 저장해야 할 정보 목록을 작성해 주세요.**    
    - 게임 회차 정보:
        - 게임의 고유 ID
        - 해당 게임에서 사용되는 보드판의 고유 ID
        - 해당 게임을 플레이하는 사용자들의 고유 ID
        - 사용자들의 고유 ID와 연결된 사용자(팀) 이름 정보
        - 장기판 기물의 표시 설정이 존재한다면 설정 옵션이 무엇인지에 대한 정보
    - 게임의 진행상황:
        - 보드판의 상태: 보드판 위 각 기물들의 고유 ID 및 기물 종류와 기물들의 현재 위치 좌표를 연결해둔 정보. 각 기물들이 어떤 팀에 소속되어 있는지에 관한 정보.
        - 플레이어의 차례: 저장 시점에 따라 누구의 차례가 막 끝난 참인지 또는 누구의 차례가 시작될 것인지에 대한 정보.
    - 기타:
        - 만일 정보를 저장할 공간이 한정되어 있다면, 비용을 줄이기 위해 '정보가 만료되는 시점' 이라는 정보를 가져도 좋을 것 같음.


- **Q. 저장 시점에 대한 분석 내용을 작성해 주세요.**
    - 게임이 시작될 때, 생성된 게임과 사용자들의 정보에 대한 저장이 일어나야 함.
    - 게임 시작 후 보드의 초기화 전략이 선택될 때마다 사용자들의 정보와 함께 저장이 일어나야 함.
    - 보드가 초기화 완료되면 저장이 일어나야 함.
    - 보드판의 상태가 변할 때마다 저장이 일어나야 함. (보드판의 상태가 변하는 시점과 팀의 차례가 변하는 시점이 동일하므로 보드판의 상태가 변하는 시점으로 통일)
    - 만일 플레이어가 자신이 어떤 말을 선택했었는지 등의 디테일한 진행 상황까지 저장되도록 구현해야 하는 상황이라면, 플레이어가 움직일 말을 정했을 때 저장이 일어나야 함.
    - 게임이 종료되는 시점에서 승자가 누군지 판정되고, 저장이 일어나야 함. 이때, 게임의 정책에 따라 완료된 게임으로서 DB에서 관리할 목록에서 아예 사라지거나, 게임의 완료 여부와 함께 저장되어야 함.


- **Q. 저장 로직의 위치에 대한 의견을 작성해 주세요.**
    적절한 시점에 저장 및 조회를 하기 위해서는 게임의 전체 진행 흐름을 알고 있는 Controller에서 저장 시점을 관리해야 함.
    즉, 저장 및 조회 메서드를 호출하는 시점을 Controller가 결정함. 

    실제 데이터를 저장하고 읽어오는 등의 저장 및 조회 로직의 경우, 
    기존 객체와는 다른 종류의 역할, '데이터 처리라는 새로운 책임'이 등장한 것이므로 새로운 클래스로 구현되어야 함.
    해당 클래스는 데이터를 저장하는 경로와 방법을 알고 수행할 수 있어야 함.
