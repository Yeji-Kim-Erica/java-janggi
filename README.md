# 💻 사이클1: 사전학습

장기판 초기화를 어떻게 구현할지 설계해본다. 토론 활동의 재료를 만드는 단계.

## 🧪 실험1: 보드 초기화 설계

### 📝 해볼 것

코드를 작성하지 않고, 설계만 해본다.

1. 장기판을 어떻게 표현할 것인가?
2. 기물을 어떻게 표현할 것인가?
3. 초기 배치를 어떻게 설정할 것인가?

### 🔎 관찰할 것

| 질문                         | 내 답                                    |
|----------------------------|:---------------------------------------|
| 장기판은 어떤 자료구조로 표현할 것인가?     | 2차원 기물 클래스 배열                          |
| 기물은 어떤 정보를 가지는가?           | 기물명, 시작 위치, 이동 가능 조건(이동 규칙), 생존 여부, 점수 |
| 위치 정보는 누가 관리하는가? (보드? 기물?) | 시작 위치는 기물이, 진행 위치는 보드가                 |
| 빈 칸은 어떻게 표현하는가?            | Enum? null?                            |

## 🧪 실험2: 상태 분류

### 📝 해볼 것

장기 게임에서 변하는 정보와 변하지 않는 정보를 분류한다.

### 🔎 관찰할 것

| 변하는 정보 (상태)      | 변하지 않는 정보 |
|------------------|:----------|
| 기물의 현재 위치        | 보드의 크기    |
| 기물의 생존 여부        | 기물명       |
| 기물의 이동 가능/불가능 위치 | 기물의 시작 위치 |
| 승부 종료 시점         | 기물 점수     |

### ❔ 추가 질문

| 질문                       | 내 답                                                     |
|--------------------------|:--------------------------------------------------------|
| 상태가 변할 때 누가 변경하는가?       | 플레이어의 선택이 상태에 영향을 줌                                     |
| 상태가 외부에 노출되어도 괜찮은가?      | 게임의 전개를 위해 기물의 위치 및 생존 여부는 외부에 드러나야 함                   |
| 상태가 잘못 변경되면 어떤 문제가 생기는가? | 실제 기물이 이동할 수 없는 곳까지 이동해서 가거나, <br> 기물 점수가 잘못 반영되는 등의 문제 |

## 🧪 실험3: 기물 이동 시 조건문 폭발

### 📝 해볼 것

코드를 작성하지 않고, 설계만 해본다.

1. 각 기물(차, 마, 상, 사, 장, 포, 졸)의 이동 규칙을 나열
2. 이동 가능 여부를 if/switch로 작성한다고 가정
3. 조건문이 몇 개나 필요할지 예상

### 🔎 관찰할 것

- 각 기물별 이동 규칙
  - **궁(왕)**: 궁궐 안에서만 움직일 수 있음. 방향에 관계 없이 한칸씩 움직일 수 있음. 다른 기물을 뛰어 넘을 수 없음. 시작 위치가 고정되어 있음.
  - **사**: 궁궐 안에서만 움직일 수 있음. 방향에 관계 없이 한칸씩 움직일 수 있음. 다른 기물을 뛰어 넘을 수 없음. 시작 위치가 고정되어 있음.
  - **상**: 한번에 앞/옆/뒤로 1칸, 대각선으로 2칸 움직임. 다른 기물을 뛰어 넘을 수 없음. 시작 위치를 마와 바꿀 수 있음.
  - **마**: 한번에 앞/옆/뒤로 1칸, 대각선으로 1칸 움직임. 다른 기물을 뛰어 넘을 수 없음. 시작 위치를 상과 바꿀 수 있음.
  - **차**: 직선으로 간다면 원하는 만큼 칸을 이동할 수 있음. 다른 기물을 뛰어 넘을 수 없음. 시작 위치가 고정되어 있음.
  - **포**: 포를 제외한 다른 기물을 1개 뛰어 넘거나 잡을 수 있음. 다른 기물을 뛰어 넘을 때만 앞/옆/뒤로 원하는 칸만큼 이동 가능. 시작 위치가 고정되어 있음.
  - **졸/병**: 앞/옆으로만 전진할 수 있음. (뒤/대각선으로 이동 불가) 다른 기물을 뛰어 넘을 수 없음. 시작 위치가 고정되어 있음.

| 항목               | 기록     |
|------------------|:-------|
| 예상되는 조건문 개수      | 18개 이상 |
| 가장 복잡한 기물의 이동 규칙 | 포      |

## 🧪 실험4: 확장의 어려움

### 📝 해볼 것

다음 상황을 가정하고 분석:

1. 새로운 기물 "용"을 추가한다면?
2. 기존 기물의 이동 규칙이 변경된다면?

### 🔎 관찰할 것

| 질문                        | 내 답                                                           |
|---------------------------|:--------------------------------------------------------------|
| 새 기물 추가 시 수정해야 하는 곳은?     | 새로운 기물의 클래스 생성, 각 기물들의 초기 위치                                  |
| 기존 기물 규칙 변경 시 영향 범위는?     | 보드, 해당 기물의 특징을 다룬 클래스                                         |
| 조건문이 한 곳에 모여 있으면 생기는 문제는? | 로직이 복잡해져 한눈에 이해하기 어려움 -> 이것이 조건 누락으로 이어질 수 있음, 유연한 규칙 변경이 어려움 |
| 조건문 없이 이동 규칙을 처리하는 방법은?   | 각 기물의 조건 규칙은 클래스 구현으로 관리하고, 이동 가능 상태는 상태 패턴을 활용               |
